# GRE Hard Mock app

Next.js (App Router) + TypeScript + Tailwind + Drizzle/Neon Postgres, deployed on Vercel. Questions are authored by Claude Code ahead of time as JSON (`content/tests/` mocks, `content/drill/` drill batches, `content/bank/{quant,verbal}/` bank batches) and synced into one shared **question bank** database; the webapp assembles each quiz from the bank on demand (a full mock or a custom quiz, `/create`) and never calls an LLM. Design: `docs/BANK.md`.

- **To add questions:** run `/bank-fill [quant|verbal]` (`bank:gaps` → `bank:brief` → one Write → `check` → blind → novelty → `bank:sync`, up to 3 batches; `docs/QUIZ-AUTHORING.md`, Bank batches). `/new-test` and `/new-drill` point to it.
- **Quizzes** live in each user's `quizzes` table (`testId = quiz-<id>`); a slot the bank cannot fill exactly goes down the fallback ladder, shows a Proceed / Cancel dialog and is logged in `shortfalls`. Reused items (answered before) are scored but log no item events. An item is seen once any response has its ref, and held while a ready or started quiz or an open mock attempt includes it.
- **Endless vocab:** single TC / SE items served one at a time at `/drill` (card on the verbal tab) from the bank's shared TC / SE stock (any source, unseen and unheld), aimed at untested words. New stock comes from tcse bank batches. Drill attempts have `mode: "drill"` and stay out of mock lists. "Replay misses" (`/drill?replay=1`, `mode: "replay"`) re-asks TC / SE items whose latest answer anywhere was wrong or guessed, and logs no item events (`docs/PRIORITY.md`).
- Ticking words on the /stats weakest-words list and pressing Dismiss dismisses them (event `dismissed`, untargeted until a later miss; `docs/PRIORITY.md`). Priority model for targeting weak words, quant concepts and reading skills (`data/rc_skills.json`, which shares the concepts table under areas `reading` / `argument`): `docs/PRIORITY.md`. Each quant concept and reading skill lists its sub-forms in `data/concept_variants.json` (a new concept needs an entry there and a section in `content/study/quant.json`, written as cards per `docs/STUDY-GUIDE.md`; a new skill needs an entry there). Difficulty craft: `docs/HARD-PATTERNS.md`. Levels 6–7 (calibrated against PowerPrep and official items): `docs/CALIBRATION.md`.
- **Public repo: never commit** ETS / Big Book text, the extracted corpus (`../books/extracted/`), `.env*`, or answer keys served to the client. Every test item must be original.
- Next.js here is v16: `proxy.ts` replaces middleware, `params`/`searchParams` are Promises. Read `node_modules/next/dist/docs/` before changing framework-level code.
- **Accounts and data isolation.** Sign-in is email + password, and **there is no sign-up path in the app; never add one.** Accounts are created only from the CLI: `npm run user:add -- <email>` (password from a hidden prompt), plus `user:passwd`, `user:list` and `user:remove`. Neon has two kinds of database on one branch:
  - `neondb` (`DATABASE_URL`) is the **registry**: just the `users` table (`lib/db/registry.ts`, migrations in `drizzle-registry/`), holding scrypt hashes and a 5-failure / 15-minute lockout.
  - `gre_u_<id>` is **each user's own database**, with the full schema in `lib/db/schema.ts` (migrations in `drizzle/`). Its URL is `DATABASE_URL` with the database name swapped.

  - `gre_bank` is the shared **question bank** (`lib/db/bank.ts`, migrations in `drizzle-bank/`): every item of every source by ref (`<source>:<qid>`), bodies with keys, read only by the app through `bankDb()`. `dbFor()` and the JWT check refuse it. Never delete a bank row or rename an item: retire it (`"retired": true`); an item gone from its file is marked `gone`.

  The session JWT (signed with `AUTH_SECRET`) names the user's database. App code reaches it only through `userDb()` (`lib/session.ts`), never through a global connection.
- **DB setup.** Neon is the Vercel Marketplace resource `gre-mock-db-sg` (Singapore, `aws-ap-southeast-1`), connected to the `gre-mock` project, with functions pinned to the matching `sin1` in `vercel.json`, so `DATABASE_URL` is set in every Vercel environment; `AUTH_SECRET` (≥ 32 chars) must also be set there (Production and Preview only). Locally `.env.local` holds both: `vercel env pull` brings the database variables, but not `AUTH_SECRET`, so keep the local one when pulling. The pre-move Virginia database (`us-east-1`, as of 2026-11-19) stays, disconnected, as `gre-mock-db-us-backup`, with dumps in `../db-backups/2026-11-19-us-east-1/` (outside the repo, `MANIFEST.txt` has checksums and row counts); delete it only when the user says so. A localhost URL switches to the plain `pg` driver. After a schema change, run `npm run db:generate`, then `npm run db:migrate` (registry, `gre_bank`, then every user database). `npm run bank:init` creates `gre_bank`; `npm run -s bank:sync -- <id>…|--all` (alias `register`) writes sources into it, and `npm run -s bank:verify` rebuilds every source from it and compares with the JSON. **The app needs `gre_bank` synced before a deploy that reads it.** `npm run seed` writes vocab and concepts to every user database (or one, with `--user <email>`); `npm run brief`, `bank:gaps` and `bank:brief` read one user's stats. Also `npm test`. For authoring:
  - `npm run -s check -- <id>` tags, validates and runs the quant key check (`content/verify/keys.py`) in one call;
  - `npm run -s blind -- <id> [--only ids] [--check -]` makes the blind copy for the `gre-blind-solver` agent and checks its reply;
  - `npm run -s novelty -- <id> [--only ids] [--check -]` pairs each item with the earlier items it could repeat, for the `gre-novelty-judge` agent, and checks its verdicts (`--audit quant|verbal` sweeps earlier tests);
  - `bank:sync` refuses an invalid source, and a bank batch without its blind and novelty records;
  - `npm run -s bank:gaps [-- quant|verbal]` ranks what the bank is short of (about 2 mocks ahead, plus the drill) and `npm run -s bank:brief` turns the top gaps into a batch brief;
  - `python3 scripts/session_stats.py` measures a run from its transcript.
- Vocab bank: `python3 scripts/build_vocab.py --ets data/ets_words.txt` → `data/vocab.json`, then `npm run seed`. Inputs: `data/popular_words.txt` (core), `data/extra_words.json` (secondary / extended / passage tiers), `data/definitions.json` (pos + senses per lemma, own words), `data/dropped_words.txt` (noise from the official-items mining), `data/exposure_only.txt` (words shown only in passages, never a TC / SE choice, like every passage-tier word; one showing covers them, `docs/PRIORITY.md`). A new word needs a definitions entry, or the build reports it as missing.
- Reference corpus (local only, `../books/extracted/reference/`): `python3 scripts/merge_reference.py` rebuilds `items.jsonl`, applying the page-image repairs in `reference/fixes/` (quant math, Quantity A/B, figure descriptions) and the tags for later-added concepts in `reference/concept_retags.jsonl`. Then `python3 scripts/concept_yields.py` recomputes concept yields. `scripts/pdf_text.js` does the PDFKit text extraction; `pdftoppm` (poppler) renders pages.
